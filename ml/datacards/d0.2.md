## Purpose

Supervised fine-tuning data for the Candela equity-research assistant: grounded tool use over the Candela market tools, agentic finance answers, general function calling, numeric reasoning over filings, short classic finance tasks in the Candela voice, and a general-retention slice against forgetting.

One sample is **one supervised assistant turn with its full conversation prefix** (only the final assistant message is trained on). Samples longer than 2048 tokens with the `gemma-4-12b-qat` chat template are dropped.

## Processing

1. **Normalisation** to OpenAI-style messages (`system`/`user`/`assistant` with `tool_calls` whose arguments are JSON objects, `tool` messages with `tool_call_id`). Function schemas are converted to the OpenAI `tools` format; tool names are sanitised to `[A-Za-z0-9_-]`. Source-specific system prompts that embed tool lists are replaced by a short generic prompt because the chat template renders `tools` natively.
2. **Retention by self-distillation** (ADR 0402): numeric QA (FinQA, TAT-QA and ConvFinQA train splits), sentiment and headline-topic prompts (financial tweets) and general instructions (smoltalk) are answered by the frozen QAT base with greedy decoding (`lab data distill`); an answer is kept only when its number matches the gold answer (1 % tolerance), its label matches the gold label (labels balanced across positive/negative/neutral), or, for general prompts, when it finished before the token limit. About 60 % of the prompts use the instruction format of the evaluation suites, the rest varied phrasings. ConvFinQA dialogues keep gold answers in a concise "calculation, then `Answer: <number>`" format.
3. **Quality filters**: final message must be an assistant turn; no empty user or assistant turns; tool-call arguments must be objects; boilerplate refusals, degenerate repetition and non-English answers are removed.
4. **PII scrubbing** (emails, phone numbers, SSN-like and Luhn-valid card-like numbers, IPv4 addresses replaced by placeholders): email 704, phone 89, ip 254, card 1.
5. **Deduplication**: exact (normalised text hash) and MinHash near-duplicates (128 permutations, 32 bands, 5-word shingles, Jaccard ≥ 0.85). Numeric QA is deduplicated on the question and answer only, because several questions legitimately share one filing excerpt.
6. **Decontamination**: any sample sharing a 13-gram (or, for evaluation texts shorter than 13 words, the whole word sequence) with an evaluation set is removed. Index size 575411; evaluation texts indexed: fpb 970, fiqa_sa 235, headlines 20547, finqa 1147, convfinqa 1490, tatqa 739, financebench 150, ifeval 541. Hits by suite: financebench 8, finqa 1331, tatqa 42, convfinqa 526, ifeval 1.
7. **Length cap** with the base tokenizer and the deterministic **weighted mix** above.

## Evaluation-only sets (never trained on)

Financial PhraseBank (CC-BY-NC-SA-3.0), FiQA-SA, Gold news headlines, FinanceBench (CC-BY-NC-4.0), the FinQA and TAT-QA test splits, the ConvFinQA evaluation split and IFEval. Non-commercial and unclear-license sets are used for evaluation and decontamination only.

## Known limitations

- `nemotron-agentic-finance` v2.0 publishes only the final user/assistant pair of each agent run (the tool trajectories are not included). These samples carry no Candela system prompt so the model does not learn to state filing figures from memory under the production prompt.
- Sentiment and topic training data come from short financial tweets (MIT); there is no permissive headline-question set comparable to the Gold headlines benchmark.
- Retention answers inherit the base model's mistakes on prompts where the gold check cannot see them (general prompts, reasoning text around a correct number).
- Samples are capped at 2048 tokens, the training window (ADR 0401): final answers of full five-tool analyses and comparisons do not fit and are not in the data; their tool-call turns are.
- Candela traces in this build come from the executor recorded per sample in `meta.executor`; traces from the `fake` executor reuse contract-shaped synthetic tool outputs and are meant for pipeline validation and pilots.
